# Comos: Google owner posting + protected data export

- The + Post button and composer publish permission use the **verified, pinned Google Firebase UID** for `phoeaung2076@gmail.com`. This email is checked by Firebase Admin on the server only; requests cannot choose an email or claim admin. Existing trusted admin configuration is retained for the other Admin tabs, but top-level post creation is reserved for the Google owner.
- To download an export: sign into the *live* Comos site as the Google owner, open **Characters → Admin Panel → Character controls**, and select **Download users & characters backup**. The server generates a fresh JSON file from saved SQLite records plus sanitized Firebase directory entries. Active and archived admin character records are both included. No user, character or backup contents are added to GitHub.
- The JSON includes stored app users, linked identities, characters, groups, posts/replies, item records and media **metadata**. Firebase directory includes UID, email, display name and provider names when available. Passwords, authentication tokens, service account credentials, and **media file bytes** are never included. If Firebase directory enumeration is unavailable, the file contains a warning; SQLite records remain included.
- This is a **manual data export**, not a scheduled whole-system backup, a Firebase Auth restorable export, a snapshot of media bytes or an automatic restore feature. Keep downloaded files private. Historical backups and data that exist only on another device/NAS cannot be imported without those files.
- The download route `/api/v1/admin/backup` requires a valid same-site session and server-verified Google owner UID. It returns 401 signed out, 403 for everyone else, and a no-store attachment for the owner.
- Basic checks: sign in with Google owner, verify the + button appears in Home, publish a title + post and reload; download JSON from Character controls and check `records.users` and `records.characters` (including archived characters). Signed-in other users can read/reply but do not see + and cannot download the backup. Check Google owner after a new session/restart. Full signed-in live testing remains required.
